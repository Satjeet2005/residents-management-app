# Decision log

Every row is a decision that was made and confirmed. The numbers are fixed:
D24, D25, D28 to D32 and D59 are not in this log, and are left unused so that
the numbers other documents quote do not change. Rows D1 to D58 are product and
design decisions. Rows D60 to D69 are engineering decisions made during the
build.

"Where in code" names the file or test that implements the decision today.
"Not built yet" means nothing in the repository implements it so far. A table
name such as `payment_attempts` is defined in `prisma/schema.prisma` and its
migration, even where the code that uses the table does not exist yet.

The one-sentence reasons were written when this log was compiled. They state why
the decision helps; they are not quotes from the people who decided.

| D7 | Bank statements use one canonical CSV schema, uploaded by hand. A separate parser turns the narration into hints. Row keys are idempotent. Every row ends in exactly one state. ## Engineering decisions made during the build

| ID | Decision | Reason | Status | Where in code |
|---|---|---|---|---|
| D60 | Invariants I1 to I8, J1 to J8, K1 to K9 and L1 are enforced in SQL (checks, unique indexes, triggers, foreign keys), and each has a named test. | The database refuses bad rows whatever code writes them. | Confirmed | `prisma/migrations/20261104080217_init_schema/migration.sql` (I), `20261104083542_bank_statements_and_matching/migration.sql` (J), `20261104091653_complaints_outbox_audit_visitors/migration.sql` (K), `20261104094500_same_flat_composite_foreign_keys/migration.sql` (L); tests in `tests/integration/`. |
| D61 | Append-only triggers on `ledger_entries`, `payment_matches`, `complaint_events`, `classifications` and `audit_log`. UPDATE, DELETE and TRUNCATE are rejected. | History must not be rewritten, and corrections are new entries. | Confirmed | Triggers `*_no_update_delete` and `*_no_truncate` in the three migrations above; `tests/integration/ledger-invariants.test.ts` (I3), `payment-matches-invariants.test.ts` (J4), `complaint-support-invariants.test.ts` (K5), `truncate.test.ts`. |
| D62 | Composite foreign keys keep related rows on one flat. | A ledger entry cannot point at another flat's bill, even by mistake. | Confirmed | `prisma/migrations/20261104094500_same_flat_composite_foreign_keys/migration.sql`; `tests/integration/same-flat-invariants.test.ts` (L1). |
| D63 | Money is BigInt paise everywhere, and `Money` is the only formatter. | No floats means no rounding drift, and one formatter means one display rule. | Confirmed | `src/domain/money/money.ts`; `src/components/ui/money.tsx`; `tests/domain/money.test.ts`; `tests/integration/bigint.test.ts`. |
| D64 | The late fee is computed from dates and is never stored. | A stored fee goes stale when a payment or a hold changes. | Confirmed | `src/domain/billing/late-fee.ts`; `src/domain/time/calendar.ts`; `tests/domain/late-fee.test.ts`. |
| D65 | An import allowlist keeps `src/domain` pure. | The domain can be tested without a framework or a database. | Confirmed | `eslint.config.mjs` (`no-restricted-imports`); `tests/architecture.test.ts`; `tests/domain-imports.test.ts`. |
| D66 | Dependency policy: exact versions, published at least 14 days ago, with `npm audit` before and after. | Pinned and aged packages reduce the risk of a bad release. | Confirmed | `CLAUDE.md`; exact versions in `package.json`. |
| D67 | CI runs gitleaks over the full history, with a pinned binary whose checksum is verified. | A secret in an old commit is still a leak, and an unverified binary is a supply-chain risk. | Confirmed | `.github/workflows/ci.yml` (step "gitleaks (full history, pinned CLI)"); `scripts/scan-secrets.mjs` for the local scan. |
| D68 | The seed is deterministic and guarded: `DEMO_MODE`, `--yes`, `--confirm-database`, and allowlists of hosts and database names. | A seed or reset must never hit the wrong database, and a fixed seed gives repeatable tests. | Confirmed | `src/server/seed/guards.ts`; `src/server/seed/cli.ts`; `src/domain/seed/prng.ts`; `tests/server/seed-guards.test.ts`; `tests/domain/seed/dataset-determinism.test.ts`; `docs/seed-data.md` ("Guards"). |
| D69 | Tests stay under 3 s each on 2 CPUs. | CI runs on 2 vCPUs with a 5 s default timeout. | Confirmed | `CLAUDE.md`; each task report lists the slowest ten tests. No test enforces it. |
