# scripts

Developer and CI scripts (e.g. `scan-secrets.mjs`). No application logic.

- `smoke-app.mjs`: the resident pages and the pay flow over real HTTP against the built app: login, the Home numbers, Pay, a stale amount, a signed success and failure, bad signatures, the demo checkout's 404 and 307, the failure strip, and a staff import of the sample bank statement through the demo route (summary counts, a second upload skipped as repeats, a resident refused with 403), the reconciliation screens (start page, workspace with its books check and lane counts, the review panel, the Awaiting approval lane as requester and as approver, and who is turned away), a manual match approved by a second user (D116), and the complaints routes (a water leak raised with the keyword fallback, a gas complaint on the duty manager's SAFETY lane, acknowledged and closed, a resolve, a confirm, 403 for a resident on the staff routes); it reads `src/server/statements/sample-statement.ts` with Node's type stripping). `node scripts/smoke-app.mjs <BASE_URL> --as-of=<YYYY-MM-DD|real> --demo=true`. For the pay flow the script needs the server's `PAYMENT_WEBHOOK_SECRET` in its own environment; it signs events with it and never prints it.
- `smoke-auth.mjs`: checks login, `/api/me`, logout-all and the cookie over real HTTP against a running server. `npm run smoke:auth -- <BASE_URL> <demo phone>`. Needs the server in demo mode; prints lengths, never the code, token or cookie.
- `smoke-readiness.mjs`: the first step of both smoke scripts (D112). It reads `GET /api/health/ready`, prints each check as PASS, FAIL or INFO (the report holds no values), and when the deployment is not ready it stops with a message naming the failing checks, before any login is tried. It is not run on its own. `--allow-owner-role` (local development only, refused unless the host is localhost or 127.0.0.1) lets an owner connection pass (D139).
- `llm-check.ts`: a human-run check of the complaint classifier's provider keys (D140). `npm run llm:check` reads `.env` (if it exists) and, for each configured provider (`JEV_PRIMARY_*`, `JEV_SECONDARY_*`), sends three fixed fictional complaints and prints one line per provider and sample: the provider name, the HTTP status, the latency, the top category and the top urgency with their probabilities. It prints `model: provider default` or `model: set` (never the name) per provider, adds a hint to set `JEV_<PROVIDER>_MODEL` when a provider with no model answers 400 or 422, prints one plain line for a provider that is invalid (`opencode: invalid (URL_NOT_HTTPS), not checked: look at JEV_PRIMARY_URL`) or not configured, a line for the shared settings (default, set or invalid), never prints a key, a URL or a response body, and exits 1 when no configured provider answered (an invalid setting has no exit code of its own: it is named and the check goes on, D145). It uses the real network and the free tiers' quota (three calls per provider); no test runs it.
- `logs.ts` (`npm run logs:errors`): the developer's reader for `error_events` (D135). It reads only `LOGS_DATABASE_URL` (the read-only logs role; refuses without it), prints the host and database name, reads in a READ ONLY transaction and redacts every row again. `--since`, `--ref`, `--digest`, `--request-id`, `--route`, `--level`, `--source`, `--limit`, `--json`, `--paste`.
- `prune-errors.ts` (`npm run db:prune-errors`): deletes `error_events` rows older than N days with the owner `DATABASE_URL` of your shell; needs `--yes` and `--confirm-database=<name>` (and `--allow-remote` for a hosted database); prints only the number deleted.
- `test-ci-parity.sh` (`npm run test:ci-parity`): runs `npm run test:unit` and `npm run test:integration` the way CI does, under `env -i` with `IGNORE_DOTENV=true` and only `PATH`, `HOME`, `NODE_OPTIONS` and `DATABASE_URL` (the caller's, else the value in `.env.example`). `IGNORE_DOTENV=true` makes the integration config, `prisma.config.ts` and the seed CLI skip loading `.env`. Needs the database running. Run it before you push.
- `make-icons.ts` (`npm run icons`): renders `public/icons/mark.svg` to the PNG icons of the web app manifest and iOS (192, 512, maskable 512, and a 180 touch icon) with the Chromium of Playwright. The SVG and the PNGs are committed; a build does not run it.
- `verify-clean-clone.sh`: run by a HUMAN in an EMPTY temporary directory: `bash scripts/verify-clean-clone.sh <repository-url> [--quick]`, or `--local-copy <dir>` to copy a directory instead of cloning. It checks Node against `.nvmrc`, runs `npm ci`, writes a local `.env` from `.env.example` with fresh random `OTP_PEPPER` and `PAYMENT_WEBHOOK_SECRET` (nothing secret is printed), starts its OWN database container (a unique `COMPOSE_PROJECT_NAME` and a free `DB_PORT`; `VCC_DB_PORT` and `VCC_APP_PORT` choose ports and it refuses clearly when one is taken), migrates, seeds, builds, starts the app on a free port, runs `smoke:auth` for a resident and a staff phone, and runs `test:ci-parity` unless `--quick`. It then stops only what it started (the server by its PID, its own compose project with `down -v`) and prints a PASS/FAIL table; the exit status is non-zero if any step failed. It first removes `DATABASE_URL`, `DEMO_AS_OF`, `OTP_PEPPER` and the other variables that could redirect the run from its own shell (a `DATABASE_URL` in your shell would otherwise beat `.env` and aim the migration and the seed at another database), and sets its own. It deletes no directory. `--skip-install` is TEST ONLY: it links `node_modules` from the repository the script lives in instead of running `npm ci`, and the `npm ci` row then reads SKIP.
