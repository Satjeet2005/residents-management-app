# scripts

Developer and CI scripts (e.g. `scan-secrets.mjs`). No application logic.

- `smoke-app.mjs`: the resident pages and the pay flow over real HTTP against the built app: login, the Home numbers, Pay, a stale amount, a signed success and failure, bad signatures, the demo checkout's 404 and 307, the failure strip, and a staff import of the sample bank statement through the demo route (summary counts, a second upload skipped as repeats, a resident refused with 403), the reconciliation screens (start page, workspace with its books check and lane counts, the review panel, the Awaiting approval lane as requester and as approver, and who is turned away), a manual match approved by a second user (D116), and the complaints routes (a water leak raised with the keyword fallback, a gas complaint on the duty manager's SAFETY lane, acknowledged and closed, a resolve, a confirm, 403 for a resident on the staff routes); it reads `src/server/statements/sample-statement.ts` with Node's type stripping). `node scripts/smoke-app.mjs <BASE_URL> --as-of=<YYYY-MM-DD|real> --demo=true`. For the pay flow the script needs the server's `PAYMENT_WEBHOOK_SECRET` in its own environment; it signs events with it and never prints it.
- `smoke-auth.mjs`: checks login, `/api/me`, logout-all and the cookie over real HTTP against a running server. `npm run smoke:auth -- <BASE_URL> <demo phone>`. Needs the server in demo mode; prints lengths, never the code, token or cookie.
- `llm-check.ts`: a human-run check of the complaint classifier's provider keys (D140). `npm run llm:check` reads `.env` (if it exists) and, for each configured provider (`JEV_PRIMARY_*`, `JEV_SECONDARY_*`), sends three fixed fictional complaints and prints one line per provider and sample: the provider name, the HTTP status, the latency, the top category and the top urgency with their probabilities. It says which variable is missing for a provider that is not configured, never prints a key, a URL or a response body, and exits 1 when no configured provider answered (2 for an invalid setting). It uses the real network and the free tiers' quota (three calls per provider); no test runs it.
- `test-ci-parity.sh` (`npm run test:ci-parity`): runs `npm run test:unit` and `npm run test:integration` the way CI does, under `env -i` with `IGNORE_DOTENV=true` and only `PATH`, `HOME`, `NODE_OPTIONS` and `DATABASE_URL` (the caller's, else the value in `.env.example`). `IGNORE_DOTENV=true` makes the integration config, `prisma.config.ts` and the seed CLI skip loading `.env`. Needs the database running. Run it before you push.
